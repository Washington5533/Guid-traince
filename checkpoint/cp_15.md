# cp_15 · 模型管线可视化 (ModelVisualizer)

**文件**: `guardian/model_viz.py`
**阶段**: 跨实验（训练后可随时运行）
**核心目标**: 不用读代码猜数据流向——一键生成可交互 HTML 流程图

> **AI 提权**: AI 主导可视化配置（展开/折叠/分组/着色）和瓶颈分析。用户确认后渲染。

---

## 为什么需要

阅读模型代码来理解数据流是低效的。F10 自动解析模型结构，计算每层的 FLOPs/参数量，用颜色标注瓶颈，生成可交互 HTML。

## 核心流程

```
模型入口 (train:build_model)
  → 规则引擎解析: torch.fx / named_modules → 节点 + 边
  → 规则引擎计算: FLOPs 估算 + 参数统计
  → AI 提议: 展开/折叠/分组/着色 + 瓶颈标注 + 架构概述
  → 终端展示提案
  → 用户确认/NL修正
  → 渲染 HTML (vis-network + D3)
```

## AI 决策边界

| 维度 | Standalone | MCP |
|------|-----------|-----|
| **能做** | 定义展开/折叠/分组/着色策略；标注瓶颈+优化建议；架构概述 | 上述全部 + 读源码定位瓶颈层 + 改模型代码 + 重新可视化验证 |
| **不能做** | 修改模型代码（standalone）；解析模型结构（规则引擎） | —（Claude Code permission 约束） |
| **人把关** | 可视化配置需确认，支持 NL 修正 | Claude Code 修改需用户 approve |
| **降级** | AI 不可用 → 默认展开全部、按 stage 分组、按 FLOPs 着色、规则瓶颈判定 | 断开 → 回退 standalone |

## MCP 工具

- `get_model_structure(model_entry)`: 返回模型结构 JSON（节点 + 边 + FLOPs 统计）
- `run_visualization(model_entry, output_path)`: 触发 HTML 生成

## 关键类与方法

```
ModelVisualizer(config, advisor)
  - parse_model(model_fn) → dict       # 规则引擎：torch.fx / named_modules
  - compute_stats(graph) → dict        # FLOPs + params + 每层占比
  - propose_config(graph, stats, user_feedback) → dict  # AI 提议
  - render_html(graph, stats, viz_config, output_path) → Path
  - visualize(model_fn, output_path) → dict  # 主入口
  - print_proposal(viz_config, stats) → str   # 终端展示
```
